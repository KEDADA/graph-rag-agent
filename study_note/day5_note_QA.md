## 一、实体消歧（Entity Disambiguation）

### Q1: 什么是实体消歧？为什么需要它？

**参考答案**：
实体消歧是将不同的mention（实体表达）映射到同一个canonical_id（规范实体ID）的过程。

需要它的原因：
- LLM提取实体时，同一实体可能用不同表达出现（如"习近平"、"习总书记"、"国家主席习近平"）
- 不做消歧会导致图谱中出现大量重复节点
- 影响检索召回率和图谱质量

---

### Q2: 实体消歧的三步管道是什么？每步的作用是什么？

**参考答案**：

**阶段1：字符串召回（String Recall）**
- 方法：Levenshtein编辑距离
- 作用：快速召回Top-K候选实体
- 阈值：`DISAMBIG_STRING_THRESHOLD=0.6`
- 特点：召回率优先，速度快

**阶段2：向量重排（Vector Rerank）**
- 方法：计算mention和候选的embedding余弦相似度
- 作用：用语义相似度精排候选
- 公式：`combined_score = 0.4*字符串相似度 + 0.6*向量相似度`
- 特点：精确度优先，语义理解

**阶段3：NIL检测（NIL Detection）**
- 方法：检查最佳候选的combined_score
- 作用：判断是否为新实体（Not In Lexicon）
- 阈值：`DISAMBIG_NIL_THRESHOLD=0.75`
- 特点：避免误合并

---

### Q3: 为什么组合打分用`0.4*字符串 + 0.6*向量`，而不是`0.5*字符串 + 0.5*向量`？

**参考答案**：
1. **语义更重要**：向量相似度捕获语义信息，比字符串匹配更准确
2. **经验验证**：0.6的权重在多个数据集上表现最好
3. **容错性**：即使字符串差异大（如"习近平"vs"习总书记"），向量相似度高仍能正确匹配
4. **可调整**：不同领域可以根据实际数据调整权重

---

### Q4: 什么是NIL检测？阈值如何确定？

**参考答案**：

**NIL（Not In Lexicon）**：判断mention是否为知识库中未登录的新实体。

**阈值确定方法**：
1. **经验值**：0.75是经过实验验证的经验值
2. **权衡**：
   - 阈值太低 → 误合并（把不同实体合并）
   - 阈值太高 → 漏检（把相同实体判定为NIL）
3. **领域相关**：不同领域的实体命名规范不同，需要根据实际数据调整
4. **A/B测试**：在验证集上测试不同阈值，选择F1-score最高的

---

### Q5: 实体消歧如何应用到图谱？WCC分组的作用是什么？

**参考答案**：

**应用流程**：
1. 先用Neo4j GDS的WCC算法，将图谱分成多个弱连通分量
2. 同一个WCC内的实体更可能是同一个实体的不同表达
3. 对每个WCC分组，选择**度数最高**的实体作为canonical_id
4. 其他实体的`canonical_id`字段指向它

**WCC分组的作用**：
- **减少搜索空间**：只在同一连通分量内比较，避免全图遍历
- **提高准确性**：连通分量内的实体有关系连接，更可能是同一实体
- **批量处理**：分页处理WCC分组，避免内存溢出

## 二、实体对齐（Entity Alignment）

### Q6: 实体对齐和实体消歧有什么区别？

**参考答案**：

**实体消歧**：
- 目标：将不同mention映射到同一个canonical_id
- 输入：mention（实体表达）
- 输出：canonical_id
- 时机：在图构建过程中

**实体对齐**：
- 目标：将指向同一canonical_id的多个实体合并成一个
- 输入：canonical_id分组
- 输出：去重后的图谱
- 时机：在消歧之后

**关系**：消歧是"指针"，对齐是"合并"。

---

### Q7: 实体对齐的冲突检测用什么方法？为什么？

**参考答案**：

**方法**：Jaccard相似度

**公式**：
```
Jaccard = |交集| / |并集|

实体A的关系: {申请, 评选, 资助}
实体B的关系: {申请, 管理}

交集: {申请}
并集: {申请, 评选, 资助, 管理}

Jaccard = 1 / 4 = 0.25
```

**为什么用Jaccard而不是余弦相似度？**
1. **数据类型**：关系类型是离散集合，不是连续向量
2. **Jaccard定义**：专门用于集合相似度计算
3. **余弦相似度**：适用于连续向量，需要先转换为one-hot向量
4. **可解释性**：Jaccard更直观，0.5表示"一半的关系类型重叠"

---

### Q8: 实体对齐时如何解决冲突？

**参考答案**：

**冲突判定**：
- 计算关系类型的Jaccard相似度
- 如果Jaccard < `ALIGNMENT_CONFLICT_THRESHOLD`（默认0.5）→ 存在冲突

**冲突解决策略**：
1. **LLM介入**：
   - 将冲突实体的描述和关系数喂给LLM
   - LLM选择最合适的实体
2. **回退策略**：
   - 如果LLM调用失败，选择**关系数最多**的实体
   - 理由：关系数多的实体信息更丰富

---

### Q9: 实体合并时如何处理关系？为什么用CALL子查询？

**参考答案**：

**关系处理**：
1. 将要删除实体的所有出边和入边转移到目标实体
2. 检查目标实体是否已有相同类型和属性的关系
3. 只有不存在重复关系时才创建新关系
4. 删除旧实体

**为什么用CALL子查询？**
- **隔离边处理**：即使某个实体没有边，子查询返回0，主流程继续执行
- **避免失败**：不用CALL的话，如果`OPTIONAL MATCH`没有匹配到边，整个查询会失败
- **保证原子性**：确保`SET`和`DELETE`操作始终执行

## 三、社区检测（Community Detection）

### Q10: 为什么需要社区检测？

**参考答案**：

**核心问题**：知识图谱可能有数万甚至数十万个实体，如何快速回答全局性问题？

**举例**：
```
问题: "学生资助体系包括哪些类型？"
传统方法: 遍历所有实体 → O(n)复杂度，太慢
社区检测: 先找到"学生资助"社区 → 只在社区内搜索 → O(k)，k << n
```

**社区检测的目标**：
1. 将图谱划分成多个紧密连接的子图（社区）
2. 社区内部连接密集，社区之间连接稀疏
3. 为全局搜索提供预聚合的上下文（社区摘要）

---

### Q11: Leiden算法和SLLPA算法有什么区别？各自适用什么场景？

**参考答案**：

| 算法 | 原理 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|----------|
| **Leiden** | 基于模块度优化的层次聚类 | 结果稳定，社区质量高 | 计算复杂度高，大图慢 | 中小规模图谱（<10万节点） |
| **SLLPA** | Speaker-Listener标签传播 | 速度快，支持重叠社区 | 结果不稳定，依赖初始化 | 大规模图谱，Leiden不收敛时回退 |

**本项目策略**：
- 默认使用Leiden
- 如果Leiden不收敛或超时，自动回退到SLLPA

---

### Q12: 什么是模块度（Modularity）？Q值多少算好？

**参考答案**：

**模块度定义**：
```
Q = (社区内部边数 - 期望边数) / 总边数

Q ∈ [-0.5, 1]
```

**Q值判断标准**：
- Q < 0.3：社区结构不明显，可能是随机图
- 0.3 ≤ Q < 0.7：社区结构明显
- Q ≥ 0.7：社区结构非常强

> 💡 **通俗理解：班级小团伙类比**
> 
> 想象一个班级，大家互相交朋友（建立连线）。你想把班里分成几个小团体（社区）。
> 怎么分才好？直觉上：**小团体内部的人应该关系极好（边很多），不同小团体之间互相不理睬（边极少）**。
> 
> $Q$ 值翻译成白话文就是：
> $Q = (这个圈子实际的朋友边数 - 如果大家瞎蒙乱交朋友，理应出现的期望边数) / 班级总边数$
> 
> **核心逻辑是寻找“超越随机的惊喜”：**
> 如果这个小圈子的实际交互量**远远高于**随机概率（即 分子很大），说明这群人**绝不是随机凑到一起的，而是真正铁板一块的小团体**。Leiden 算法就是在不断试错地把人移来移去，只保留能让全班总 $Q$ 值增加的操作，直到 $Q$ 达到顶峰，这时切分出的社区质量就是最高的。

**本项目经验**：
- Q值通常在0.5-0.7之间，表示社区结构良好
- Q值不是越高越好，过高可能意味着社区过于孤立

---

### Q13: 为什么需要层次社区结构？

**参考答案**：

**层次结构示例**：
```
实体A → 社区0-1 (level=0, 最细粒度)
         ↓
      社区1-5 (level=1, 中等粒度)
         ↓
      社区2-2 (level=2, 最粗粒度)
```

**需要层次结构的原因**：
1. **多粒度问题**：不同问题需要不同粒度的上下文
   - 细粒度（level=0）：具体问题，如"国家奖学金的申请条件"
   - 粗粒度（level=2）：宏观问题，如"学生资助体系的整体结构"
2. **动态路由**：根据问题复杂度，Agent可以选择合适层级的社区
3. **减少噪声**：粗粒度社区过滤了细节噪声，更适合全局性问题
4. **可扩展性**：层次结构支持图谱规模增长，不需要重新划分社区

---

### Q14: Leiden算法的gamma参数有什么作用？如何调整？

**参考答案**：

**gamma参数**：分辨率参数，控制社区的粒度

**作用**：
- gamma越大 → 社区越小（更细粒度）
- gamma越小 → 社区越大（更粗粒度）

**调整策略**：
```python
# 社区过多（每个社区只有几个实体）
'gamma': 0.5,  # 降低gamma → 社区更大

# 社区过少（社区太大，失去分区意义）
'gamma': 1.5,  # 提高gamma → 社区更小
```

**经验值**：
- 小图谱（<1000节点）：gamma=0.5-0.8
- 中图谱（1000-10000节点）：gamma=1.0
- 大图谱（>10000节点）：gamma=1.2-1.5

---

### Q15: 社区摘要生成的流程是什么？为什么不直接用实体列表？

**参考答案**：

**摘要生成流程**：
1. 提取社区内所有实体和关系
2. 构建社区子图的文本描述
3. 调用LLM生成摘要（包含：主题、关键实体、关系类型）
4. 将摘要存储到`__Community__`节点的`summary`属性
5. 为摘要生成embedding，用于语义检索

**为什么不直接用实体列表？**
1. **语义压缩**：摘要将数百个实体压缩成几句话，减少LLM上下文长度
2. **可读性**：摘要更易于理解，实体列表只是ID，缺乏语义信息
3. **向量检索**：摘要的embedding更能代表社区的整体语义，检索效果更好
4. **LLM友好**：摘要是自然语言，LLM可以直接理解并生成回答

## 四、综合应用

### Q16: 实体消歧、实体对齐、社区检测的执行顺序是什么？为什么？

**参考答案**：

**执行顺序**：
```python
1. 知识图谱构建（实体提取）
2. 实体消歧
3. 实体对齐
4. 社区检测
5. 社区摘要生成
6. 构建索引
```

**为什么必须按这个顺序？**
- **消歧依赖实体的embedding**：需要先提取实体并生成embedding
- **对齐依赖消歧的canonical_id**：需要先知道哪些实体指向同一个ID
- **社区检测依赖对齐后的干净图谱**：去重后的图谱更准确
- **索引构建依赖社区结构**：全局搜索需要社区摘要

### Q17: 如果消歧召回率低，如何调优？

**参考答案**：

**问题表现**：很多mention被判定为NIL，但实际上图谱中存在对应实体。

**原因分析**：
- `DISAMBIG_STRING_THRESHOLD`太高，字符串召回阶段过滤了正确候选
- `DISAMBIG_NIL_THRESHOLD`太高，向量重排后分数不够

**解决方案**：
```env
# 降低阈值
DISAMBIG_STRING_THRESHOLD=0.5  # 从0.6降到0.5
DISAMBIG_NIL_THRESHOLD=0.7     # 从0.75降到0.7
```

**验证方法**：
- 在验证集上测试不同阈值
- 计算召回率、精确率、F1-score
- 选择F1-score最高的阈值

---

### Q18: 如果Leiden算法不收敛怎么办？

**参考答案**：

**问题表现**：Leiden算法运行超时或内存溢出。

**原因分析**：
- 图谱规模太大（>10万节点）
- 内存不足

**解决方案**：

**方案1：降低精度参数**
```env
GDS_MEMORY_LIMIT=8  # 增加内存限制
GDS_CONCURRENCY=2   # 降低并行度
```

**方案2：切换到SLLPA算法**
```env
GRAPH_COMMUNITY_ALGORITHM=sllpa
```

**方案3：图预处理**
- 移除孤立节点（度数为0）
- 移除低权重边（weight < 阈值）
- 合并多重边

**方案4：分批处理**
- 先对WCC（连通分量）分别运行社区检测
- 再合并结果

## 五、面试STAR话术

### Q19: 用STAR法则描述实体消歧的实现

**参考答案**：

**S（Situation）**：知识图谱构建时，LLM提取的实体存在大量重复，同一实体用不同表达出现（如"习总书记"和"习近平"），导致图谱节点冗余，检索召回率低。

**T（Task）**：设计并实现实体消歧管道，将不同mention映射到唯一的canonical_id，确保图谱实体的唯一性。

**A（Action）**：
1. **字符串召回**：用Levenshtein编辑距离快速召回Top-K候选（阈值0.6）
2. **向量重排**：计算mention和候选的embedding余弦相似度，组合打分（0.4字符串+0.6向量）
3. **NIL检测**：若最佳候选分数<0.75，判定为新实体，避免误合并
4. **WCC分组**：结合图结构的弱连通分量，批量处理同一连通分量内的实体，选择度数最高的作为canonical

**R（Result）**：实体消歧后，图谱节点去重率提升约30%，检索召回率提高15%，为后续搜索提供了更高质量的图谱基础。

---

### Q20: 用STAR法则描述社区检测的实现

**参考答案**：

**S（Situation）**：知识图谱包含数万个实体，全局性问题（如"学生资助体系包括哪些类型？"）需要遍历所有实体，检索效率低。

**T（Task）**：实现社区检测算法，将图谱划分成紧密连接的子图，为全局搜索提供预聚合的上下文。

**A（Action）**：
1. **Leiden算法**：基于模块度优化的层次聚类，生成多层社区结构（level 0-2）
2. **自适应参数**：根据系统内存动态调整gamma、tolerance、maxLevels，平衡精度和性能
3. **SLLPA回退**：当Leiden不收敛时，自动切换到标签传播算法
4. **社区摘要**：为每个社区生成LLM摘要，包含主题、关键实体、关系类型，并生成embedding用于语义检索
5. **层次存储**：将社区结构存储为`__Community__`节点，通过`IN_COMMUNITY`关系连接实体和社区

**R（Result）**：社区检测后，全局搜索的检索时间从平均5秒降低到1.2秒，模块度Q值达到0.68，社区结构明显，为全局搜索提供了高质量的预聚合上下文。

## 七、实战操作题

### Q24: 如何验证实体消歧是否成功？

**参考答案**：

**在Neo4j Browser中执行**：
```cypher
// 1. 查看消歧结果
MATCH (e:`__Entity__`)
WHERE e.canonical_id IS NOT NULL
RETURN e.id, e.canonical_id, e.disambiguated
LIMIT 10

// 2. 统计消歧率
MATCH (e:`__Entity__`)
RETURN count(e) AS total_entities,
       count(e.canonical_id) AS disambiguated_entities,
       100.0 * count(e.canonical_id) / count(e) AS disambiguation_rate
```

### Q25: 如何验证社区检测的质量？

**参考答案**：

**在Neo4j Browser中执行**：
```cypher
// 1. 查看社区数量和分布
MATCH (e:`__Entity__`)-[:IN_COMMUNITY]->(c:`__Community__`)
RETURN c.level, count(DISTINCT c) AS community_count, count(e) AS entity_count
ORDER BY c.level

// 2. 查看最大的10个社区
MATCH (e:`__Entity__`)-[:IN_COMMUNITY]->(c:`__Community__`)
WHERE c.level = 0
RETURN c.id, count(e) AS entity_count
ORDER BY entity_count DESC
LIMIT 10

// 3. 查看社区摘要
MATCH (c:`__Community__`)
WHERE c.summary IS NOT NULL
RETURN c.id, c.level, c.summary
LIMIT 5
```

**质量指标**：
